# Portfolio

Express/EJS 포트폴리오와 Supabase 방문 통계.

## 방문 통계

- `/who`: 관리자용 방문 통계. 브라우저 로그인 창에서 관리자 계정을 입력합니다.
- 선택일 방문자: 한국 시간 00:00 이상, 다음 날 00:00 미만의 고유 IP 수.
- 선택일 접속 횟수: 페이지 이동 및 새로고침을 포함한 페이지 GET 요청 수.
- IP별 선택일·전체 기간 접속 횟수와 최근 방문 시간, 50개씩 페이지 이동.
- 선택일까지 최근 30일 통계, 선택일 최근 접속 기록 200건, 표시된 기록 검색.
- 누적·일별 합계는 최근 200건 제한과 무관하게 DB 전체 기록에서 집계합니다.
- 관리자 페이지, 추적 API, 정적 파일, 404, HEAD, prefetch는 집계하지 않습니다.
- 실제 사람 수와 고유 IP 수는 다릅니다. 공유 IP 및 봇 요청도 있을 수 있습니다.

## Supabase 설정

1. 사용할 Supabase 프로젝트가 활성 상태인지 확인합니다.
2. 프로젝트 SQL Editor에서 `supabase/setup.sql`을 실행합니다.
   포트폴리오 전용 테이블, 인덱스, 집계 함수를 만듭니다. 다른 앱 테이블은 변경하지 않습니다.
3. `.env.example`을 `.env`로 복사하고 서버 환경 변수를 설정합니다.
   - `POSTGRES_URL`: Vercel의 Supabase 연결이 자동으로 추가하는 서버 전용 연결 문자열.
   - `WHO_ADMIN_USERNAME`: 관리자 이름(기본값 admin).
   - `WHO_ADMIN_PASSWORD`: 방문 통계 관리자 비밀번호.
4. Vercel의 기존 Portfolio 프로젝트에 같은 환경 변수를 추가한 뒤 재배포합니다.
   비밀 키와 비밀번호를 GitHub, HTML, 클라이언트 JS에 넣지 마세요.
5. 포트폴리오 페이지를 두 번 방문한 뒤 통계에서 접속 2회, 고유 IP 1개 증가를 확인합니다.
   관리자 화면 새로고침은 방문 기록을 추가하지 않습니다.

운영 사이트는 HTTPS를 사용해야 합니다. 관리자 인증은 JSON 조회 경로에도 적용됩니다.
인증 설정이 없으면 관리자 화면은 닫힌 상태(503)로 유지합니다.
테이블은 RLS를 활성화하고 공개·일반 로그인 역할의 테이블 및 함수 접근을 회수합니다.
서버의 Postgres 연결만 저장·조회하므로 공개 RLS 정책을 만들지 않습니다.

기존 MySQL/visitors.json 기록은 자동으로 가져오지 않습니다. 연동 이후 기록부터 쌓입니다.
DB 요청은 5초 제한이며 저장 실패 시에도 포트폴리오는 계속 표시됩니다.

## 실행 및 검증

Node.js 22 이상:

```sh
npm ci
npm start
npm test
npm ci --prefix test/sql
npm run test:sql
```

SQL 테스트는 메모리 내 PostgreSQL(PGlite)에서 동작하며 운영 DB를 변경하지 않습니다.
KST 날짜 경계, 반복 IP, 200건 이상 합계, 페이지 이동, 익명/일반 사용자 접근 차단을 검증합니다.
HTTP 테스트는 Supabase 응답을 모의 처리해 중복 기록, 관리자 인증, 오류 처리, HTML 이스케이프를 검증합니다.
실제 Supabase/Vercel 연동 검증은 설정 및 배포가 완료된 뒤 별도로 수행해야 합니다.
